# Buffer production acquisition during database outages

Production acquisition targets PostgreSQL/TimescaleDB. While the host is running, the application must commit batches returned by the DAQ to a persistent local disk buffer promptly and retain at least 24 hours of data at the configured production rate during a database outage. Committed batches are replayed without duplication when the database returns or the application process restarts. A process crash between a DAQ read and the disk commit may lose that in-flight batch; this is accepted and must appear as an acquisition gap when detectable. If the application cannot retain further samples, it must stop acquisition and report a gap rather than silently drop data. The guarantee does not cover samples produced while the host is powered off or while the application is unable to read the DAQ. Loss of historical database data after a database storage failure is accepted.
